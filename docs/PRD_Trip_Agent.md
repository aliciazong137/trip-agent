## 1. 产品概述

### 1.1 产品定位与愿景
**Trip Agent** 是一款基于大语言模型（LLM）与高德地图（AMap）JS API 2.0 深度融合的 **AI 原生随身旅行管家（AI-Native Personal Travel Agent）**。

产品打破了传统旅行软件“先在聊天框问答，再切换到死板地图”的孤立体验，采用**双态灵动画布（Dynamic Canvas）**架构，将 AI 自然语言规划与高德真实地理空间数据实时同屏联动，为用户提供从“意图输入 → 智能行程生成 → 路线地图查看 → 分步导航引流”的连续、流畅、极具未来感的 C 端旅行体验。

### 1.2 目标用户与使用场景
- **目标用户**：追求高效、个性化旅行体验的自由行游客、周末短途游爱好者、C 端移动端用户。
- **典型场景**：
  - **灵感规划**：用户输入“南京 3 天 2 夜休闲游，想吃美食少走路”，Agent 智能生成每日打卡点与合理顺序。
  - **地图查看**：在手机上边看高德真实路线轨迹（驾车/公交/步行/骑行），边查分步时间轴与换乘指引。
  - **现场导航**：在旅行途中，一键地图内启动导航或唤起高德地图原生 App 进行真实 GPS 导航。

## 2. 核心设计原则与创新亮点（Refined UX/UI）

为拒绝平庸、提升 UI 原型的“新意与科技感”，设计遵循以下原则：

1. **Canvas-First（画布优先）**：地图不只是背景，而是交互的主舞台（Main Stage）。所有行程节点、路线 Polyline 和动画效果均在地图画布上平滑呈现。
2. **Dynamic Island / Capsule Widgets（灵动胶囊控制）**：摒弃传统死板的 Tab 栏与侧边栏，采用类 iOS 灵动岛的悬浮磨砂玻璃胶囊（Glassmorphism Capsules），随操作动态收缩/扩展。
3. **Dual-Mode Canvas（双态画布）**：
   - **探索态（Explore Mode）**：AI 对话与澄清卡片悬浮于地图上方，对话生成路线时，地图上的 Marker 和 Polyline 逐个渐变亮起（Stream-drawing）。
   - **执行态（Navigate/Tour Mode）**：对话框收起为底部灵动输入条，底部向上滑出磨砂玻璃行程抽屉（BottomSheet Drawer），专注于路线查看与导航。
4. **Mobile-First App Shell（移动优先与 PWA 支持）**：手机端打开即呈现在地 App 质感，桌面端自适应为手机宽度容器，支持“添加到主屏幕（PWA）”。

```text

│                       Trip Agent App                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                      双 态 灵 动 画 布                       │

│  [Tab 1: 💡 灵感对话]   [Tab 2: 🗺️ 路线地图]   [Tab 3: 👤 我的] │
│   - 自然语言生成行程     - 高德真实路线绘制     - 历史行程列表 │
│   - 智能澄清交互卡片     - 折叠时间轴抽屉       - 出行偏好设置 │
│   - 路线生成预览         - 一键导航 / 唤起 App  - PWA 安装引导 │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│   [ 💡 灵感 ]           [ 🗺️ 行程地图 ]          [ 👤 我的 ]  │ ← 悬浮 App Dock 栏
└─────────────────────────────────────────────────────────────┘
```

### 3.2 用户主旅程 (User Journey)
1. **触发意图**：用户在 [💡 灵感] Tab 输入旅行需求（自然语言）。
2. **Agent 交互与澄清**：Agent 后端解析意图；若信息缺失，在界面抛出轻量芯片（Chip）卡片引导补全。
3. **路线渲染**：Agent 返回生成结果，自动平滑无缝无感切到 [🗺️ 行程地图] Tab，高德地图实时绘制路线轨迹。
4. **行程探索**：用户在地图上方切换 `D1/D2/D3` 或 `驾车/公交/步行/骑行`，底部抽屉跟随刷新时间轴。
5. **现场导航**：点击时间轴上的 `[🚀 导航]`，启动地图内路线分步面板或唤起高德地图原生 App。

## 4. 详细功能模块需求 (Functional Requirements)

### 4.1 模块 A：AI 灵动对话与意图识别 (Agent Hub)
- **自然语言输入**：支持多轮对话，对接后端 `POST /api/trip/plan-nl`。
- **智能澄清卡片 (Clarification Chips)**：当后端返回需澄清字段（如交通偏好、预算）时，前端渲染非阻塞式的悬浮选择 Chip（不用用户手动打字）。
- **行程生成预览卡片**：生成成功后吐出带城市封面图、天数、主要打卡点的海报卡片，点击一键全屏展开地图。

### 4.2 模块 B：高德真实路线地图 (Amap Map Canvas)
- **多模式官方插件绘制**：
  - **驾车 (`AMap.Driving`)**：支持起终点与中间途经点（Waypoints），显示实时路况颜色（畅通/拥堵）。
  - **公共交通 (`AMap.Transfer`)**：解析并展示公交/地铁线路名、上下车站、乘坐站数、步行接驳。
  - **步行 (`AMap.Walking`) / 骑行 (`AMap.Riding`)**：绘制真实路网轨迹与关键转向指引。
- **顶部灵动控制胶囊 (Top Dynamic Segment)**：
  - 左侧：日期切换 Pill (`第 1 天` / `第 2 天` ...)。
  - 右侧：交通方式切换 Pill (`驾车` | `公共交通` | `步行` | `骑行`)。
- **底部折叠时间轴抽屉 (Collapsible BottomSheet)**：
  - **收起态**：显示总里程、预计耗时、起终点摘要，右侧保留突出 `[🚀 导航]` 按钮。
  - **展开态**：纵向链式时间轴，公共交通可按路段展开/折叠显示具体步骤（openLegs）。
  - **联动响应**：点击时间轴某节点，地图自动 `setFitView` 并高亮对应 Marker。

### 4.3 模块 C：导航引流与端外唤起 (Navigation Bridge)
- **地图内路线面板**：驾车/步行/骑行点击导航时，利用高德插件 `panel` 在地图侧边/底部渲染官方分步指引。
- **原生 App 唤起 (URI Scheme)**：提供标准高德 URI 链接，一键唤起手机已安装的高德地图 App 开展真实 GPS 语音导航：
  `amapuri://route/plan/?sourceApplication=TripAgent&dlat={lat}&dlon={lng}&dname={name}&dev=0&m={mode}`

### 4.4 模块 D：移动端 App 壳与 PWA (Mobile Shell)
- **响应式视口**：`viewport` 配置 `viewport-fit=cover`，全面适配 iOS / Android 底部 Home 条与顶部刘海安全区。
- **桌面端模拟器**：桌面浏览器打开时，呈现高质感居中手机 Frame 容器（430px 宽度）。
- **PWA 支持**：配置 `manifest.webmanifest` 与 Apple Touch Icon，允许用户“添加到主屏幕”作为独立 WebApp 打开。

## 5. 接口与数据契约 (API & Data Contracts)

### 5.1 后端 API 对接列表
1. **自然语言生成行程**：`POST /api/trip/plan-nl`
   - 入参：`{ "query": "南京3天游，驾车", "session_id": "xxx" }`
2. **获取 Session 详情**：`GET /api/trip/session/{session_id}`
3. **获取地图与路线点**：`GET /api/trip/session/{session_id}/map`
   - 返回结构（符合前端 `MapData`）：
     ```json
     {
       "city": "南京",
       "days": [
         {
           "day": 1,
           "city": "南京",
           "transportation": "驾车",
           "points": [
             { "order": 1, "poi_id": "p1", "name": "中山陵", "location": { "longitude": 118.856, "latitude": 32.058 } },
             { "order": 2, "poi_id": "p2", "name": "明孝陵", "location": { "longitude": 118.839, "latitude": 32.061 } }
           ]
         }
       ]
     }
     ```

## 6. 非功能性需求与验收标准 (Non-Functional & Acceptance Criteria)

### 6.1 性能与体验
- 地图初始化加载时间 < 1.5 秒。
- 切换天数与交通方式时，路线重绘无明显闪烁或旧轨迹残留。
- 移动端滑动底部抽屉需达到 60fps 的流畅跟手度。

### 6.2 最终验收标准
1. 前端包含完整 [💡 灵感] [🗺️ 行程地图] [👤 我的] 三大 Tab 与底部悬浮 App Dock 栏。
2. 手机端浏览器打开表现为单列全屏移动 App 体验，无横向溢出与滚动条。
3. 桌面端自动呈现居中高保真手机 Shell。
4. 高德地图真实 Polyline 路线、折叠时间轴、导航唤起等核心地图能力稳定可用。
5. 前端构建与 TypeScript 类型检查 100% 通过。
